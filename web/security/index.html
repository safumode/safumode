NO MAGIC / FOUR HARD EDGES

Where protection ends.

01

A delay only helps if someone acts.

For an untrusted destination, a valid authorizer signature starts a waiting period. Either authority can cancel a queued exit, but the vault does not monitor itself. Once the wait is over, execution may beat cancellation.

02

Recovery goes to one fixed place.

The recovery authority can move assets immediately, but only to the recipient chosen when the vault was created. If that recipient’s key is lost or compromised, the contract cannot change it.

03

Pause can become a permanent lock.

Either authority can pause alone. Both must approve a resume. If one key is permanently lost while paused, there is no on-chain way to restart withdrawals or rotate the keys.

04

Not every token can safely leave.

The vault requires the exact signed amount to leave and arrive. Fee-charging, rebasing, frozen, or unusual ERC-20 tokens can fail that check. A successful deposit does not prove a token can be withdrawn; there is no admin rescue route.

FOR A CLOSER READ

Questions worth asking.

Can the withdrawal key take everything instantly?

It can authorize an immediate exit only to an address that is already trusted in the current authority epoch. To a new destination, a valid signed request must wait the configured delay. A compromised key can still schedule that request; monitoring and a timely cancellation are essential.

Can two signatures always rescue the funds?

No. The recovery recipient is fixed when the vault is created. Recovery is immediate to that address, not to a new one. Unsupported tokens can be stranded even if both signers agree. If a key is lost while paused, both-key resume is impossible.

Does the website prove a vault is genuine?

No. The read-only tool can compare a supplied address, chain and bytecode to its static allowlist. An RPC can lie about what it reports, and there is no endorsed public deployment on that allowlist. Cross-check chain evidence independently.

What does the delay cover?

It covers ordinary withdrawals to untrusted recipients, adding a trusted recipient, and rotating both authorities. A trusted-recipient withdrawal and recovery to the fixed recipient can be immediate. The delay is configured when a vault is deployed; it is not a universal number.
