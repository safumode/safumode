01 / THE IDEA

One wallet to use.
Another key to approve.

Put funds in the vault with your daily wallet. To take them out, a separate withdrawal key has to sign. You can keep that key on a Ledger. Sending to a new address also starts a waiting period so there is time to cancel.

This does not protect you if the separate approval key is compromised or you approve a malicious withdrawal. Lose both controlling keys and there is no support desk that can restore access.

TRUSTED ROUTE

The authorizer signs. A recipient already active in the current authority epoch can receive the withdrawal without the untrusted-recipient delay.

DELAYED ROUTE

The authorizer signs, then policy adds the configured waiting period. Either authority can cancel before later execution.

RECOVERY EXCEPTION

The recovery authority can transfer immediately, only to the immutable recovery recipient, while the vault is unpaused. The withdrawal delay does not apply.

02

EXIT AUTHORITY

Withdrawal key

Signs withdrawal requests while remaining separate from the everyday wallet.

  • Trusted route can be immediate
  • Untrusted route waits
  • Cannot alone establish trust
03

BOUNDED RECOVERY

Recovery key

Pauses, cancels and recovers only to the fixed recovery recipient.

  • Co-approves trust and rotation
  • Can veto pending rotation
  • Cannot choose a new recovery destination
03 / RECOVERY LIMITS

A recovery path
is not a reset button.

Recovery is intentionally powerful and intentionally constrained. Its destination is fixed. There is no operator who can change it for you.

CAN

Contain an incident

Either current authority can pause. Pending withdrawals can be cancelled. A pending rotation can be vetoed.

REQUIRES BOTH

Change sensitive policy

Resuming, adding a trusted recipient, and scheduling authority rotation require both current authorities.

CANNOT

Undo permanent loss

If both authority keys are lost, the contract provides no administrator recovery. Loss of the fixed recipient key can make recovered assets inaccessible.
